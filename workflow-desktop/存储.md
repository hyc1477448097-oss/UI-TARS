# 项目存储机制总结

## 一、全局存储一览

| 存储 | 类型 | 存什么 | 重启丢不丢 |
|---|---|---|---|
| SQLite | 磁盘持久化 | runs、run_events、projects | 不丢 |
| Hub | 内存 | RunSession（含 Event、浏览器、LLM） | **丢** |
| LangGraph State | 内存 | 工作流执行中间状态 | **丢** |
| Playwright | 内存 | 浏览器连接和页面 | **丢** |
| WebSocket | 内存 | 前端订阅连接 | **丢** |

核心设计：**数据库负责持久化（记录发生了什么），内存负责运行时协调（控制流程怎么走）**。

---

## 二、数据库（SQLite）

**文件**：`data/workflow.db`

### 表结构

| 表 | 存什么 | 生命周期 |
|---|---|---|
| `runs` | 每次执行的主记录（id、状态、项目、开始/结束时间） | 持久化，重启不丢 |
| `run_events` | 执行过程中产生的事件（步骤、消息、payload） | 持久化，重启不丢 |
| `projects` | 知识库项目（从 YAML 加载） | 持久化，重启不丢 |

### 全局对象

- `engine` — SQLAlchemy 引擎，连接 SQLite
- `SessionLocal` — session 工厂，每次 `with SessionLocal()` 创建独立会话
- `Base` — ORM 基类

### 访问方式

```python
with SessionLocal() as session:
    session.query(Run)...       # 查询
    session.add(Run(...))       # 新增
    session.commit()            # 提交
```

### 谁在用

| 函数 | 位置 | 做什么 |
|---|---|---|
| `has_active_run()` | `runtime.py` | 查是否有活跃任务 |
| `create_run()` | `runtime.py` | 插入新 run 记录 |
| `update_run()` | `runtime.py` | 更新 run 状态/错误信息 |
| `get_run()` | `runtime.py` | 查询单个 run 详情 |
| `delete_run()` | `runtime.py` | 删除 run 及关联事件 |
| `cleanup_runs()` | `runtime.py` | 批量清理旧 run |
| `RunSession.emit()` | `runtime.py` | 写入 run_events 表 |
| `reload_knowledge()` | `knowledge.py` | 读写 projects 表 |

## 三、Hub（内存）

**全局对象**：`hub = Hub()`（`runtime.py`）

```python
class Hub:
    sessions: dict[str, RunSession]

hub.register(run_id)    # 创建 session，存入 hub.sessions[run_id]
hub.get(run_id)         # 取出 session
hub.drop(run_id)        # 删除 session
```

### 存储内容

每个 `RunSession` 包含：

- `run_id` — 关联的执行任务
- `confirm_event` / `abort_event` — `asyncio.Event`，用于等待/唤醒
- `subscribers` — WebSocket 订阅者队列
- `pending_confirm` — 待确认的操作信息
- `chrome` — 浏览器连接实例
- `llm` — 大模型连接实例

### 谁在用

| 调用方 | 做什么 |
|---|---|
| 启动逻辑 | `hub.register(run_id)` — 创建 session |
| `decide` 节点 | `hub.get(run_id)` → 取 LLM 实例、判断危险操作 |
| `wait_confirm` 节点 | `hub.get(run_id)` → 取 Event 等待确认 |
| `act` 节点 | `hub.get(run_id)` → 取浏览器执行操作 |
| `finalize` 节点 | `hub.get(run_id)` → 取浏览器关闭、取 Event |
| API `api_confirm` | `hub.get(run_id)` → `confirm_event.set()` |
| API `api_abort` | `hub.get(run_id)` → `abort_event.set()` |

工作流各节点里的快捷方式：

```python
def _session(run_id: str) -> RunSession:
    return hub.get(run_id)  # 内部还是走 hub.get
```

### 类比前端

Hub 类似于前端的 **Pinia**（Vue 状态管理库）——都是内存中的集中式存储，通过统一的接口访问。区别是 Hub 更简单，本质就是一个 dict 包装（注册表模式），而 Pinia 有响应式、computed 等丰富功能。

如果前端用了 Pinia，数据流是：

```
前端 Pinia（前端状态）  ←→  API / WebSocket  ←→  Hub（后端状态）
```

## 四、LangGraph State（内存）

**全局对象**：`workflow_app = build_graph()`（编译好的图）

每次执行创建初始 `WorkflowState` 字典，在工作流节点间自动传递。

### 访问方式

```python
async def decide(state: WorkflowState) -> dict:
    state["config"]       # 读
    state["history"]      # 读
    return {"last_action": action}  # 写（返回新值，框架合并到 state）
```

### 各节点读写

| 节点 | 读什么 | 写什么 |
|---|---|---|
| `prepare` | config, kind, extras | 初始化状态 |
| `observe` | run_id | screenshot, step_count |
| `decide` | config, history, step_count | last_action, needs_confirm |
| `wait_confirm` | run_id, needs_confirm | needs_confirm=False |
| `act` | last_action, history, step_count | history, status |
| `route_after_*` | last_action, status, step_count | 只读，决定路由 |
| `finalize` | status, step_count, error, last_action | status, error |

## 五、Playwright 浏览器连接（内存）

挂在 `session.chrome` 上，通过 `ChromeOperator` 管理。

### 访问方式

```python
chrome = _chrome(state["run_id"])   # 从 session 上取 ChromeOperator
chrome.execute(action)               # 执行操作
chrome.page_text()                   # 获取页面文本
chrome.close_tab()                   # 关闭标签页
chrome.disconnect()                  # 断开连接
```

### 谁在用

`open_page`（打开页面）、`observe`（截图）、`act`（执行操作）、`finalize`（关闭销毁）

---

## 六、WebSocket 连接（内存）

通过 `session.subscribers`（挂在 RunSession 上）：

```python
session.emit("log", "xxx", step="act")
# 内部遍历 session.subscribers 里的 asyncio.Queue，逐个 put 消息
# WebSocket 端点那边 await queue.get() 取消息，发给前端
```

前端连接断开后，对应的 Queue 自动从 subscribers 列表移除。

---

## 七、访问关系总览

```
                    ┌─── hub.get(run_id) ──→ RunSession ──→ Event / chrome / subscribers
                    │
工作流节点 ──┤─── state["xxx"] ──→ LangGraph State（内存）
                    │
                    └─── SessionLocal() ──→ SQLite（runs / run_events / projects）

API 接口  ──── hub.get(run_id) ──→ RunSession ──→ event.set()
```

---

## 八、注意事项

- 重启后端服务后，Hub、LangGraph State、Playwright、WebSocket 全部丢失
- 数据库里的 run 记录不会丢，但状态可能卡在 `running` 或 `waiting_confirm`，与内存不一致
- 手动清除卡住的任务：直接改数据库 `UPDATE runs SET status='aborted' WHERE id='任务id'`
- 前端刷新不影响后端内存状态，只会断开 WebSocket（自动重连）
